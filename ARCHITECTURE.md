# Архитектура: от Telegram-бота к персональному "второму мозгу"

Этот документ фиксирует решения, принятые в обсуждении после security-хардненинга (см. историю git), чтобы не держать их только в переписке. Обновляется по мере реализации.

## 1. Структура Obsidian-vault (PARA + Zettelkasten)

Папки в Google Drive / Obsidian:

```
00-Inbox/       — сырое, необработанное (Inbox.md, Raw_Inbox.md)
01-Daily/       — Tasks.md, Health.md, Finance.md (без изменений)
02-Projects/    — подпапка на каждый проект с дедлайном
03-Areas/       — сферы жизни без дедлайна (Учёба/Расписание.md и т.д.)
04-Resources/   — Zettelkasten-заметки (знания, статьи, идеи)
05-Media/       — фильмы/аниме/книги/игры
06-People/      — карточки людей
07-Archive/     — закрытое/неактуальное (Icebox)
08-System/      — Profile.json, Flashcards.json, Memory.md, Questions.md, Index.json
```

Папки создаются ботом автоматически при старте (как и сейчас) — вручную в Drive/Obsidian ничего создавать не нужно.

## 2. Frontmatter-шаблоны по типам заметок

Вместо произвольного текста — YAML-шапка + тело. Даёт возможность позже строить таблицы через Obsidian Dataview.

- **resource**: `category, tags, source, created`
- **media**: `category (anime|movie|series|book|game), status (planned|watching|watched|dropped), rating, date_finished, tags`
- **person**: `relationship, met_where, met_date, tags` — тело дополняется датированными записями, не перезаписывается
- **project**: `status, deadline, area, tags`

## 3. Index.json — резолюция сущностей

`08-System/Index.json` — список известных тегов/людей/проектов/тайтлов с путями к файлам. Подмешивается в промпт Archivist-агента перед созданием/обновлением заметки, чтобы:
- не плодить дубли карточек одного человека/тайтла/проекта (upsert, а не всегда create);
- переиспользовать существующие теги вместо изобретения новых.

## 4. Роутинг сообщений (Router)

Расширение с 5 до 8 категорий: `TASK, FINANCE, HEALTH, QUESTION, MEDIA, PERSON, PROJECT, RESOURCE` (RESOURCE — бывший NOTE, дефолтный Zettelkasten-тип). Ссылка в сообщении по-прежнему форсирует RESOURCE.

## 5. Агенты и модели

Основная цепочка (hot path): **Router → Archivist → Chat/QA**.
Фоновые: **Indexer** (сверка тегов/сущностей с Index.json), **Tutor** (уже фоновый, генерация флеш-карт).

Модели: `gemini-3.8-flash` — основная рабочая лошадка везде, кроме мест, где критична задержка (инлайн-режим, дашборд) — там `gemini-3.5-flash-lite`/`gemini-3.1-flash-lite`.

5 ключей Gemini: у каждой роли — предпочитаемый ключ, 5-й — общий резерв при отказе (429/503) остальных. `key_manager.py` также должен временно исключать ключ, который систематически (не разово) отваливается, а не долбиться в него по кругу.

## 6. Telegram UX — прозрачность процесса

Вместо одного `typing`-индикатора — сообщение-статус, редактируемое по стадиям пайплайна ("🧠 Анализирую...", "📝 Создаю заметку...", "✅ готово"), с пометкой, если сработал fallback на резервный ключ/модель.

## 7. Данные с носимых устройств (Honor MagicWatch 2)

Цепочка: часы → приложение Honor Health (BT-синк) → **Health Sync** (сторонний Android-мост, без root) → Google Fit / Health Connect → ежедневный джоб бота читает API и пишет **одну агрегированную запись в день** в Health.md (средний пульс, шаги, фазы сна, стресс).

Важно: сырые высокочастотные данные **не** льются в Obsidian напрямую — `write_file_to_drive` перезаписывает файл целиком при каждой записи (нет серверной дозаписи в Drive API), поэтому только агрегаты.

## 8. Расписание университета

`03-Areas/Учёба/Расписание.md` с двумя разделами — "Нечётная неделя" / "Чётная неделя". Обновление — вручную пользователем (сайт вуза меняется редко, парсить не будем, надёжнее ручного ввода). Ежедневный джоб считает чётность недели от даты начала семестра и подставляет сегодняшние пары в Tasks.md.

## 9. Отложено (не блокирует реализацию выше)

- Геолокация — способ ещё не выбран (вероятно, через телефон).
- Голосовой вывод (TTS, Jarvis-стиль) — отдельные модели/тарифы, вне текущего бесплатного пула.

## 10. Порядок реализации

Идём шагами, каждый — отдельный коммит(ы), не ломая текущее поведение бота между шагами:

1. **Структура папок** — переименовать/добавить папки под PARA в `vault_files.py`/`drive_service.py`, без изменения логики агентов.
2. **Frontmatter-шаблоны + Index.json** — базовые примитивы чтения/записи (переиспользуя `update_json_file_on_drive` из хардненинг-сессии).
3. **Расширение Router + новые типы заметок** (MEDIA/PERSON/PROJECT) в `ai_pipeline.py`.
4. **Indexer-агент** — сверка тегов/сущностей.
5. **Апгрейд моделей** (`gemini-3.8-flash` и т.д.) + устойчивость `key_manager.py` (закреплённые роли, исключение мёртвых ключей).
6. **Telegram UX** — статус-сообщения по стадиям.
7. **Расписание университета**.
8. **Интеграция часов** (Google Fit/Health Connect чтение + агрегация).

Локация и голосовой вывод — вне этого списка, до отдельного обсуждения.
